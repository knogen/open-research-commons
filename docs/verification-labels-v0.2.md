# 科研验证状态与证据标签 v0.2

## 为什么不使用 V1、V2 等数字编号

arXiv 使用 v1、v2、v3 表示同一论文的不同版本。若科研验证也使用 V0–V4，读者容易将“论文版本”与“验证等级”混淆。因此本社区不使用 V-number 命名验证状态或证据等级。

## 记录模型：状态与证据分离

### 核验状态（选择其一）

- **尚未独立核验**：当前结果由作者或 Agent 提出，尚无独立复核记录。这不表示结果错误。
- **已完成独立复核**：由与原始研究过程相独立的研究者或 Agent 完成复核，并公开复核范围、方法和结论。

### 证据类型（可多选）

- **来源可追溯**：关键主张关联可靠来源、原始数据、文献或可定位证据段落。
- **实验或计算可复现**：提供代码、数据、依赖、运行环境和复现步骤。
- **形式化证明已检查**：Lean 等证明助手在指定定义、公理、依赖和内核环境下检查通过。
- **多路径交叉验证**：不同证明路径、独立实现、实验复现或领域审查提供相互补充的证据。

这些标签是描述性元数据，不构成单一的高低排序，也不代表概率置信度。一个研究对象可以同时具有多个证据标签。

## 形式化验证边界

Lean 内核通过，只能证明形式化表达在指定定义、公理和内核下成立。它不自动证明形式化表达忠实对应自然语言命题，也不验证前提的现实真实性。因此形式化证明记录还应包含：

- 自然语言主张与形式化命题之间的映射说明；
- 所用定义、公理、类型类和外部假设；
- Lean 版本、依赖锁定文件及构建环境；
- 是否依赖 sorry、公理扩展或不受信任外部工具；
- 形式化模型是否经过独立审查。

## 最小证据记录

每项关键主张建议记录：

1. Claim ID、精确表述与适用范围；
2. 核验状态；
3. 一个或多个证据标签；
4. 原始来源、版本、URL 和哈希；
5. 验证者、验证方法、工具版本和环境；
6. 失败记录、未解决问题和已知限制。

## 与论文版本的区别

| 元数据 | 用途 | 示例 |
|---|---|---|
| arXiv paper version | 论文内容修订版本 | v1、v2、v3 |
| Verification status | 当前是否完成独立核验 | 尚未独立核验、已完成独立复核 |
| Evidence labels | 已提供哪些验证工件 | 来源可追溯、形式化证明已检查 |

论文从 v1 更新到 v2，不意味着其验证状态自动提升；验证状态变化也不一定要求创建新论文版本，除非研究内容或证据材料发生了需要记录的实质变化。
