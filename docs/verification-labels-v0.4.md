## 1. 适用范围与核查原则

本规范初期服务数学及相关研究，适用于论文、证明、研究代码和配套材料。每项核查绑定明确的研究对象、主张和版本；可以覆盖全文，也可以只覆盖一个引理、一个推导步骤、一段程序或一组计算。公开发表后，社区可以持续核查和补充。

~~Lean 是可选方法，不是全站统一投稿门槛。作者可以提供逐步论证核查、独立推导、其他形式化工具检查、可复现计算、反例搜索或补充材料，并说明这些方法实际检查了什么。~~

以数学定理或证明为主要结论的投稿，应提供支撑主要结论的形式化证明文件，并注明文件对应的具体结论。Lean 是主要支持工具，也接受符合社区公布标准的其他形式化证明系统。人工核查、计算与反例搜索等可作为核查记录，不替代上述投稿要求。是否需要社区再次检查验证，依编辑稿仍列为讨论问题。

不同方法不自动具有相同的证明效力；方法名称和完成程度均不替代核查结论。[依据：Issue #2](https://github.com/knogen/open-research-commons/issues/2)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

人提出问题、Agent 找到核心思路并完成证明、随后由人类研究者逐步核查的成果，可以按宪章第四章提交发表。责任主体必须如实说明分工，披露核查记录和未解决问题，并负责回应质疑。核查者不必声称自己提出了核心思路；作者或责任代表的检查也不自动成为独立复核。[依据：Issue #3](https://github.com/knogen/open-research-commons/issues/3)。

## 2. 核验状态、复核结论与完成程度分别记录

记录对象是指定版本中的具体主张或明确范围。不得把某一局部已完成的检查泛化为全文已获正确性保证。

### 2.1 核验状态（选择其一）

- **尚未独立核验**：所申报范围尚无已完成的独立复核记录。可能已有作者自行核查、责任代表检查、工具运行，或正在进行的社区核查；此状态不表示结果错误。
- **已完成独立复核**：与被核查论证的原始生成过程相独立的研究者或 Agent，已经完成所申报范围的复核，并公开方法、依据、范围和结论。此状态表示复核过程已完成，不表示复核结论必然支持原主张。

独立性须说明复核者与作者、原始工作流的关系，以及使用了哪些共同材料和工具。仅更换 Agent 名称、会话或模型版本，不足以自动证明独立性。作者团队参与原研究后的检查应如实记录；是否构成独立复核须依据具体关系和过程判断。

### 2.2 复核结论（与状态分开）

每条完成的核查记录必须写明结论，例如“支持所核查主张”“部分支持”“发现错误或反例”“暂无法判断”，并给出理由和适用条件。同一论文的不同主张可以有不同结论；若不同复核者结论不一致，保留各自的记录和分歧，不用一个标签抹平争议。

发现错误的独立复核同样可以是“已完成独立复核”。作者随后修订了证明，需要将新版本与旧结论关联并重新说明核查覆盖范围，不能直接沿用旧版本的支持性结论。

### 2.3 完成程度（说明覆盖范围）

记录已完成部分、未完成部分、正在进行的检查和明确排除的内容。可以写“引理 2 已完成逐步核查；定理 1 的归纳步骤待检查”，不以一个无分母的百分比替代覆盖清单。局部核查及局部证明材料应注明其范围；以数学定理或证明为主要结论的投稿，仍须提供支撑主要结论的形式化证明文件。

上述区分用于落实方法、覆盖范围、完成程度和依据的披露要求。[依据：Issue #2](https://github.com/knogen/open-research-commons/issues/2)、[Issue #3](https://github.com/knogen/open-research-commons/issues/3)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

## 3. 证据类型（可多选，不设高低等级）

| 证据标签 | 使用条件与边界 |
|---|---|
| **来源可追溯** | 关键主张关联来源、原始数据、文献或可定位的证据段落，并区分来源直接陈述、作者推论和待验证假设。能找到来源不等于来源或推论已被证实。 |
| **复现材料已提供** | 已提供所申报范围的代码、数据或证明文件、依赖、运行环境说明和操作步骤。材料清单应说明缺失项和访问限制；仅列出文件不等于材料已经齐备，更不等于成功复现。 |
| **逐步论证已核查** | 已按声明范围逐步检查论证、推导或证明，并保留检查人、步骤、依据和结论。检查可以发现错误；标签本身不表示全部步骤正确，也不自动表示独立复核。 |
| **实验或计算可复现** | 在指定版本和环境下已有可审查的成功运行或复现记录，并记录复现目标、步骤、实际输出及其与预期的关系。必须区分作者自行运行与独立复现；仅有材料不能使用此标签，部分成功不能泛化为全部成功。 |
| **形式化证明已检查** | 指定形式化命题已在声明的定义、公理、依赖和检查环境下完成工具检查，并公开通过范围及记录。未完成目标、`sorry` 占位或未证明的关键假设不得计入已完成证明范围；工具运行不自动构成语义一致性审查或独立复核。 |
| **多路径交叉验证** | 对同一明确主张，已有不同推导路径、独立实现、复现或审查方式提供相互补充的实际检查记录。应说明路径之间的共享假设、依赖与分歧；多个 Agent 重述同一论证不自动构成交叉验证。 |

这些标签描述已有材料和实际检查，不构成单一高低排序，也不代表概率置信度。同一对象可有多个标签；标签必须附带范围、结论、失败记录和已知限制。“复现材料已提供”与“实验或计算可复现”分别记录准备情况和已发生的成功运行，不能互相替代。[依据：Issue #2](https://github.com/knogen/open-research-commons/issues/2)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

## 4. 数学研究的不同核查方法

| 方法 | 应公开的记录 | 结论边界 |
|---|---|---|
| 人类或 Agent 逐步核查 | 被检查的命题、逐步推导、所用定理和前提、检查意见、遗漏与争议 | 说明检查者的角色和独立性；作者确认可构成责任审查，不自动代表第三方独立复核。 |
| 独立推导或替代证明 | 新推导或证明、与原命题的对应关系、共同假设、未覆盖部分 | 只有确实覆盖同一命题及其适用条件时，才能用于支持该命题；更弱命题的证明不能冒充完整证明。 |
| Lean 或其他形式化工具 | 证明文件、命题映射、环境与依赖、运行命令、检查日志和通过范围 | 可以只形式化局部；通过的局部不得标成全文通过。形式化表达与原研究命题是否一致需要另外核查。 |
| 计算实验与数值核查 | 程序、输入数据、算法、精度、随机性设置、环境、结果和失败记录 | 普通数值样例、有限测试或近似计算不能直接作为普遍数学命题的证明。若使用穷尽计算证明有限命题，应给出穷尽范围及完整性依据。 |
| 反例搜索与边界检验 | 搜索范围、方法、候选反例、对前提的检查和复现步骤 | 找到符合前提的反例可以反驳相应全称主张；在已搜索范围内未找到反例，不等于证明不存在反例。 |
| 补充材料与来源核查 | 补充推导、定义、数据、依赖文献、来源定位、与主张的关系 | 增加材料有助于继续核查；不能仅因上传材料就声称主张已获证明。 |

方法选择应与主张类型相称。作者应说明采用该方法的理由，以及它能够支持和不能支持的结论。[依据：Issue #5](https://github.com/knogen/open-research-commons/issues/5)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

## 5. 形式化证明的专门记录

形式化检查记录必须让复核者能够判断具体检查了哪个命题、在哪些假设和工具条件下检查，以及哪些部分仍未完成。至少包括：

1. 自然语言主张与形式化命题之间的映射，文件路径、定理标识及全文或局部范围；
2. 所用定义、公理、类型类、外部假设及其依赖关系；
3. Lean 或其他工具的版本、依赖锁定文件、构建环境和可重复运行的命令；
4. 实际检查日志、检查时间、成功与失败目标、未完成证明和警告；
5. 是否依赖 `sorry`、额外公理或不受信任的外部工具，以及这些依赖影响哪些主张；
6. 自然语言对应关系与形式化模型是否经过独立审查、由谁审查、结论和未解决问题。

对于保留 `sorry`、未完成目标或待证明假设的工程，可以公开作为进行中的材料，但须将受影响目标标为未完成。已检查的其他部分应明确界定，不把工具能够运行或工程能够构建当作所有目标均已证明。额外公理或外部假设应作为结论的条件披露，不能隐去。

即使工具检查通过，也不能自动声称形式化表达忠实对应自然语言命题，或相关现实前提成立。局部检查、工具检查、语义一致性审查和独立复核分别记录。[依据：Issue #2](https://github.com/knogen/open-research-commons/issues/2)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

## 6. 每项关键主张的最小记录

| 字段 | 记录要求 |
|---|---|
| 对象与版本 | 作品版本、Claim ID、精确主张、适用范围，以及相关文件、URL、提交标识或哈希。 |
| 核验状态 | 在两种核验状态中选择其一，并链接支持该状态的记录。 |
| 证据标签 | 选择适用标签，逐一链接材料或实际检查记录；没有证据支持的标签不勾选。 |
| 方法与依据 | 使用何种核查方法、依据的定理/来源/输入、主要步骤及方法选择理由。 |
| 范围与完成程度 | 已检查、未检查、正在检查和排除部分；局部通过与整体范围的关系。 |
| 核查者与分工 | 人类或 Agent 标识、能够确认的模型名称和版本、所用工具版本、作者与核查者分工、独立性和利益关系说明。 |
| 环境与记录 | 依赖和锁定文件、运行环境、命令、必要参数、时间、日志、输出或逐步检查记录。非运行型核查注明不适用及其替代记录。 |
| 复核结论 | 支持、部分支持、发现错误/反例或暂无法判断，以及对应理由、条件和实际结果。 |
| 失败与限制 | 失败步骤、复现差异、未解决问题、缺失材料和已知限制；不得只报告成功部分。 |
| 后续处理 | 作者回复、是否采纳、关联更正或新版本、争议记录及状态更新。 |

核查尚未完成时，应填写当前进度和已知问题，不伪造完成结论。不同主张使用同一材料时可以复用链接，但应分别说明其支持关系。[依据：Issue #2](https://github.com/knogen/open-research-commons/issues/2)、[Issue #5](https://github.com/knogen/open-research-commons/issues/5)、[Issue #6](https://github.com/knogen/open-research-commons/issues/6)。

## 7. 社区参与、作者回应与平台处理

### 7.1 社区成员怎样参与

社区成员可以提交复现记录、逐步检查意见、替代推导、反例、失败结果或补充材料。每次反馈应定位到具体作品版本和主张，说明方法、依据、结果和局限，并提供可追溯的材料。可以先提出待确认的问题，但应区分疑问、已复现问题和已成立的反例。

### 7.2 作者怎样处理

~~作者或责任代表应确认收到有效反馈，进行核对并公开回复。~~

新稿规定提交责任人回应有关成果及协作说明的问题，作者或维护者可回应成员意见并决定是否将建议纳入原成果；具体受理与回应程序待配套规则规定。以下保留为实施讨论：采纳时，说明修改内容、受影响主张和关联版本；不采纳时，说明理由与证据；尚不能判断时，记录未解决问题和后续核查安排。收到一项检查意见不自动意味着作者接受其结论。

### 7.3 平台怎样处理

平台将反馈、作者回复、核查材料与相应作品版本和主张关联，保留处理记录并协调争议。平台可以组织补充复核、请求材料、记录分歧，并在依据明确后更新相关核验状态、证据标签和结论；更新应说明依据和影响范围，不静默覆盖旧记录。

平台完成格式审查、公开材料或组织复核，不等于平台保证数学结论正确。争议和申诉按[宪章 v0.4 第九章](constitution-v0.4.md)处理。纠错、失败复现、反例和补充证据均可作为有记录的社区贡献。

本节直接落实社区参与及作者、平台处理责任。[依据：Issue #5](https://github.com/knogen/open-research-commons/issues/5)，并承接[Issue #2](https://github.com/knogen/open-research-commons/issues/2)关于发表后持续检查和补充的建议。

## 8. 记录示例与版本关系

| 情景 | 应怎样记录 |
|---|---|
| 人提出问题，Agent 完成证明，责任代表逐步核查，尚无独立第三方复核 | 可记录“逐步论证已核查”，说明人机分工、范围和支持性结论；核验状态仍可为“尚未独立核验”。Lean 之外的形式化证明系统须符合社区公布标准；以数学定理或证明为主要结论的投稿仍应提交支撑主要结论的形式化证明文件。 |
| 论文只有引理 2 通过 Lean 检查 | 将“形式化证明已检查”绑定引理 2、证明文件、环境及通过记录；其他主张分别说明核查方法和完成程度，不能标为全文形式化通过。 |
| 作者已上传代码与环境说明，但尚无人成功运行 | 记录“复现材料已提供”及材料完整性，不标“实验或计算可复现”；运行中遇到的问题继续公开。 |
| 独立复核者完成核查并发现反例 | 对该主张可记录“已完成独立复核”，结论为“发现错误或反例”；关联作者回复、受影响版本及更正，不能展示为验证通过。 |

论文版本记录内容修订；核验状态记录指定范围是否完成独立复核；证据标签记录已提供的材料和已进行的检查。三者不能相互替代。本社区使用文字状态与标签，不使用容易与论文版本号混淆的字母—数字验证等级。

每次核查记录及其更正应保留历史。只有核查记录更新、研究内容未变时，可以更新记录版本而不虚构新的论文版本；研究内容或证据工件实质改变时，应关联相应新版本，并重新确认旧核查仍覆盖哪些内容。
